Multiplayer Real-Time Chat with Rooms

Live room-isolated messaging engine with presence tracking and sound cues

01 / 02

What Was Built

  • Strict Room Isolation: Messages and presence events are routed strictly via io.to(room).emit without cross-room data leakage.
  • Dynamic Presence Roster: Room member count dynamically updates via Socket.IO's internal adapter map (no zombie users).
  • Debounced Live Typing: 1,200ms input debouncing notifies room members when peers are actively drafting a message.
  • Web Audio Chimes & Timestamps: Zero-dependency dual-sine synthesizer chime (E5 → A5) and synchronized 12-hour timestamps.
  • Automated Integration Testing: Headless multi-client test suite programmatically verifying room & typing isolation.

Technology Stack & Rationale

Node.js 24 Express 4.19 Socket.IO 4.7 Vanilla HTML5/CSS3 Web Audio API
  • Zero Build-Step Friction: Direct ES6 and CSS3 served via Express eliminates webpack/vite compile steps, making demo startup instant.
  • Resilient Transport: Socket.IO handles automatic fallback between WebSocket and HTTP long-polling with native reconnection logic.
  • SPA View Switching: CSS-based state toggling enables instant lobby-to-chat transitions without tearing down socket connections.

Engineering Reflections & AI Insights

Critical Evaluation & Future Architecture

AI guidance analysis, production scaling path, and architectural uncertainties

02 / 02

What the AI Got Wrong

  • Global Broadcast Leaks: Initially proposed broadcasting all messages to all sockets and filtering on the client side (major security flaw).
  • Presence Desynchronization: Attempted naive in-memory arrays (users[]) which resulted in ghost users on sudden socket drops.
  • External Audio Fragility: Attempted to load static .mp3 files, requiring human redirection to native Web Audio oscillators.

Production Evolution

  • Horizontal Scale via Redis: Implement @socket.io/redis-adapter to broadcast room events seamlessly across multiple cluster nodes.
  • Persistent Storage: PostgreSQL / MongoDB storage for message persistence, chat history pagination, and read receipts.
  • Identity & Security: JWT-based handshake authentication, room permission ACLs, and Redis-backed token bucket rate limiting.

Least Sure About

  • Partition Message Recovery: Handling client reconnection storms during brief network dropouts without message loss or duplications.
  • Ordering & Idempotency: Guaranteeing strictly ordered message delivery across distributed servers when clients emit messages simultaneously.
  • Backpressure Limits: Managing socket buffer backpressure when a slow mobile client falls behind in high-throughput channels.
